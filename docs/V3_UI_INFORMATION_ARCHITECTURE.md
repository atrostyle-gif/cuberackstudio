# V3 UI 情報設計（初期案）

作成日: 2026-10-15
前提: 一般モードと STAFF モードは**同一画面**。STAFF 機能は認証済みにのみ表示。
最終レイアウトは未確定。本資料は情報の置き場の初期案である。

エンジン（3D、パーツ、価格計算、保存、安定 ID、STAFF バックエンド）は再利用する。

---

## 1. 設計原則

1. **1 画面** — 一般と STAFF でアプリを分けない。
2. **3D が主** — 設計作業の視線は中央キャンバスに置く。
3. **選択に反応する右ペイン** — 何も選んでいないときは寸法・見積サマリー。選んだときだけ詳細。
4. **STAFF は加算** — 一般 UI を置き換えない。認証後にレール / パネルが足される。
5. **表示と権限を分離** — クライアントは STAFF UI を隠すだけ。価格更新・共同編集書き込みはサーバー（Firebase ルール / Netlify Function）で拒否する。
6. **現行機能は残す** — マトリクスに無い機能を勝手に消さない。

## 3. NORTH（上部）— プロジェクトと状態

| グループ | 内容 | 現行からの移動 |
|----------|------|----------------|
| ブランド / ファイル名 | アプリ名、`currentFileName`、dirty | `#page-title` |
| ファイル | 開く / 上書き / 名前を付けて保存 / 最近 | 右パネル「ファイル」 |
| 履歴 | Undo / Redo / Reset（Reset は確認付き） | 右パネル「編集操作」 |
| 表示 | グリッド、ヘルプ、説明書 | 右パネル ユーティリティ |
| 出力 | 図面、見積へ送る、FIT（使用頻度低はメニュー化） | 右パネル下部と図面カード |
| アカウント | 「STAFF ログイン」または名前 + ログアウト | `#admin-menu-open-btn` |

一般ユーザーに見えるのはログインボタンまで。パスワード後の在庫・価格・共同編集は NORTH に並べない。

## 4. WEST（左）— 設計ツールバー

モード型（どれか一つ ON）を基本にする。

| ツール | 対応する現行 |
|--------|----------------|
| 選択 | 通常クリック |
| 追加 Beam | パーツトグル Beam + 長さ |
| 追加 Pole | パーツトグル Pole + 長さ |
| 接続 | 接続モード |
| 長さ変更 | 長さ変更モード |
| 板 | 棚板・壁板モード |
| 削除 | Alt+クリックの発見性を上げる（ツール ON でも可） |
| 移動 | `.cr-leftbar` 移動 |
| 回転 ±90 | 左バー |
| クラスタ削除 | 左バー |
| 自動レイアウト | 別 HTML を当面開く。後でパネル化 |

長さプリセットはツール「追加」ON のときだけ左または右に出す（現行の常時セレクトを移す）。

## 5. CENTER — 3D ワークスペース

現行 `#view` をほぼそのまま使う。

残すもの:

- Three.js シーン、OrbitControls
- Joint クリック追加、Alt 削除、Shift 脚
- プレビューメッシュ
- ヘルプ / 寸法 / カラーチャートはオーバーレイのままか、EAST に吸収

カメラ操作はヘルプを NORTH から開ける。

## 6. EAST（右）— コンテキスト

### 6.1 未選択

- 外形・芯々寸法サマリー
- 見積合計と「明細を開く」
- 製作数（あれば）

### 6.2 Joint 選択時

- 座標、脚 ON/OFF、JointSet 材質、削除

### 6.3 Beam / Pole 選択時

- 長さ（実寸 / オーダー）、材質適用、長さ変更のアンカー、削除

### 6.4 板選択時

- 材質、厚さ、削除

フル部材明細はタブまたは折りたたみ。現行 `#parts-table` の情報量は落とさない。

## 7. STAFF 領域（認証後のみ）

クライアント: `isCubeRackStaffMode()` または将来の Firebase `staff_members/{uid}`。

サーバー:

- 価格更新: Netlify Function + ID Token（`docs/V3_PRICE_AUTH_DESIGN.md`）
- 共同編集: Firestore `isMember`（`docs/V3_FIRESTORE_SECURITY.md`）
- ToDo: 同上 `todos` ルール

| 機能 | 情報設計 | 現行 |
|------|----------|------|
| オンライン / 自分 | 常時見える細いバー | `#staff-presence`（メニュー奥） |
| ToDo | STAFF ドック内リスト。追加・完了・（将来）削除 | `#staff-todo-*` |
| 在庫照合 | STAFF ドックのビュー。CSV。二重パスワードは廃止（STAFF セッションに乗せる） | `#stock-reconcile-*` |
| 価格管理 | STAFF ドック内ビューまたはモーダル。別 HTML からの段階移行 | `admin-pricing-9fd83.html` |
| 共同編集開始 | 保存済みプロジェクトが前提。未保存なら NORTH の保存を促す | `roomId()` 制約は維持 |

一般ユーザーの DOM に STAFF コントロールを出さない（表示制御）。出してもサーバーが書けなければ実害は限定的だが、誤操作防止のため隠す。

## 8. 画面遷移（同一アプリ内）

```
一般作業
  └ STAFF ログイン（モーダル）
       ├ 3D はそのまま
       ├ STAFF バー出現
       ├ ToDo / 在庫 / 価格はドック
       └ ログアウトで STAFF 帯だけ消える
自動レイアウト・見積書・図面
  └ 当面は別 HTML（iframe またはタブ）。後で CENTER のモードとして内製
```

## 9. 実装対象ファイル（情報設計を載せるとき）

UI シェルだけ後続フェーズで触る。本フェーズでは変更しない。

| 領域 | 新規の置き場（案） | 既存の接続先 |
|------|-------------------|--------------|
| NORTH | `index.html` header + 薄い `js/ui/shell.js`（未作成） | `file.js`, `history.js`, `admin-menu.js` |
| WEST | 左ツールバー DOM | `ui.js` のトグル類、`main.js` 左バー |
| CENTER | 既存 `#view` | `scene.js`, `main.js` |
| EAST | 右プロパティ | `estimate.js`, 材質ボタン、`display.js` 寸法 |
| STAFF | ドック | `admin-menu.js`, `staff-collab-mode.js`, `stock-reconcile.js` |

`main.js` の巨大な pointer ロジックはシェルから呼び出すだけにする。無理な分割は移行リスクになる。

## 10. 変更リスク（情報設計）

| リスク | 影響 | 緩和 |
|--------|------|------|
| ID 依存の `getElementById` が散在 | ボタンを動かすと無反応 | マトリクスの ID をシェルでも残すか、1 箇所で bind |
| `main.js` が DOM 構造前提 | 左バー生成が `#view` 内 | 生成先だけを引数化 |
| 見積テーブルを隠すと合計が更新されない錯覚 | ユーザー不信 | 合計は常時表示、明細は非表示可 |
| STAFF UI を一般に出す | 平文パスワード時代は危険 | 表示隠匿 + Phase 5 で書込封鎖 |
| 別 HTML を無理に iframe | 自動レイアウトの `window.opener` 依存 | 当面は別ウィンドウ維持 |
