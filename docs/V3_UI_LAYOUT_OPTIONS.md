# V3 UI レイアウト 3 案比較

作成日: 2026-10-15
評価対象: A CAD 型 / B ワークスペース型 / C ハイブリッド型
採点: 5 点満点（相対評価）。レイアウト未確定。推奨は相談用。

情報設計の領域名（NORTH / WEST / CENTER / EAST / STAFF）は `docs/V3_UI_INFORMATION_ARCHITECTURE.md` を参照。

---

## 案 A. CAD 型

左ツールバー + 中央 3D + 右プロパティ。STAFF は右の下段タブ、または右ペイン内の STAFF タブ。

```
┌──────── NORTH（薄く）─────────────────────────┐
├ WEST ┬──────── CENTER 3D ──────────┬ EAST ───┤
│ 42px │                             │ 320px   │
│ ツール│                             │ プロパティ│
│      │                             │ 見積    │
└──────┴─────────────────────────────┴─────────┘
```

STAFF 認証後: EAST に「設計 / 見積 / STAFF」タブを足す。

| 観点 | 点 | 理由 |
|------|----|------|
| 操作性（設計） | 4 | モード切替が左に集まり、CAD 習慣に近い |
| 3D 面積 | 4 | 右 320px + 左 42px。現行 380px 右パネルより 3D が広い |
| 機能拡張性 | 3 | ツール増やすと左が縦に伸びる。STAFF を右タブに詰めると一般と混ざる |
| 一般の使いやすさ | 3 | 初見は「何を押すか」が分かりにくい。保存が上に来れば現行よりは良い |

移行先:

- 左バー現行 `.cr-leftbar` + パーツトグル → WEST
- 右カード山 → EAST に再編
- 保存/Undo → NORTH
- STAFF オーバーレイ → EAST タブ（発見性は今より良いが 3D 作業中は奥）

リスク: STAFF の ToDo・在庫・価格が右タブの奥に入り、旧 `#collab-topbar` の常時表示を再現しにくい。`index.html` のカード順を一度に崩す。

## 案 B. ワークスペース型

上部コマンドバーが厚く、3D は最大。パネルは折りたたみ。

```
┌──────── NORTH（コマンドバー、グループ化）──────────┐
├────────────── CENTER 3D（ほぼ全幅）────────────────┤
│  必要時だけ EAST / WEST がオーバーレイ or ボトムシート │
└────────────────────────────────────────────────────┘
```

STAFF 認証後: NORTH 右に STAFF メニュー、パネルはコマンドから開く。

| 観点 | 点 | 理由 |
|------|----|------|
| 操作性（設計） | 3 | 追加のたびにパネルを出す必要があり、連続配置が遅い |
| 3D 面積 | 5 | 最大。FIT / 背景写真向き |
| 機能拡張性 | 4 | コマンド追加が容易。パネルは後付けできる |
| 一般の使いやすさ | 4 | 「保存が上」は直感的。一方、長さ・材質が隠れやすい |

移行先:

- 現行右パネルをすべて折りたたみドロワーへ
- 左フローティングは残しても消してもよい
- STAFF はコマンド「共同編集」等

リスク: 現行は「長さセレクトが常に見える」前提の操作。隠すとミスが増える。`getElementById` の要素を `display:none` にすると一部初期化がスキップされうる（`ui.js` の null ガードは多いが、計測・見積 DOM は常時必要）。

## 案 C. ハイブリッド型（CAD 型ベース + STAFF ワークスペース）

案 A の骨格を一般の既定にする。STAFF 認証後だけ、専用ワークスペースを**加算**する。

加算の候補（位置は未決、どれか一つ）:

1. 下端の薄いコラボバー + 右ドック（ToDo/在庫/価格）
2. 3D 上のドラッグ可能な STAFF パレット（旧 `#collab-topbar` に近い）
3. 画面右端の第 2 サイドバー（EAST の外側）

```
┌ NORTH: ファイル Undo 表示 [一般]  名前/ログアウト [STAFF時] ─┐
├ WEST ─┬──────── CENTER 3D ──────────┬ EAST（設計コンテキスト）┤
│ ツール │                             │ 選択・寸法・材質・合計   │
├────────┴─────────────────────────────┴────────────────────────┤
│ STAFF 時のみ: オンライン | ToDo | 在庫 | 価格                     │
└──────────────────────────────────────────────────────────────┘
```

| 観点 | 点 | 理由 |
|------|----|------|
| 操作性（設計） | 5 | 一般は CAD 型のまま連続配置できる。STAFF は設計を止めずに ToDo/オンラインを見られる |
| 3D 面積 | 4 | 一般時は A と同じ。STAFF 時はバー分だけ減る（折りたたみ可） |
| 機能拡張性 | 5 | STAFF 機能を一般ツールバーに混ぜない。Phase 4 の presence / ソフトロックをバーに足せる |
| 一般の使いやすさ | 4 | 未ログイン時は STAFF が消えるので右パネルが今より短い。保存が上に来る |

移行先:

- 一般機能 → A と同じ NORTH/WEST/CENTER/EAST
- STAFF オーバーレイ → 専用ワークスペース。中身の関数はそのまま bind
- 旧 STAFF `#collab-topbar` / ToDo ボタン → STAFF バーへ移植（Phase 4 と同時でも可）

リスク: シェル DOM が増える。ただし既存 ID を残して移動すればハンドラは流用できる。STAFF バーが 3D 操作と重ならないよう z-index 設計が必要。

| 案 | 操作 | 3D | 拡張 | 一般 | 合計 |
|----|------|----|------|------|------|
| A CAD | 4 | 4 | 3 | 3 | 14 |
| B ワークスペース | 3 | 5 | 4 | 4 | 16 |
| C ハイブリッド | 5 | 4 | 5 | 4 | 18 |

## 推奨: 案 C

理由:

1. 決定済み方針「同一画面 + STAFF は認証後のみ」に最も合う。
2. 現行の強み（3D 上で Joint をクリックして伸ばす）を左ツール + 中央で維持できる。
3. 現行の弱み（右パネル過密、STAFF がモーダル奥、共同編集が見えない）を、一般シェルと STAFF シェルの分離で解消できる。
4. Phase 4 の ops 共同編集・presence・ソフトロックを、STAFF ワークスペースに足せば UI を二度作り直さなくてよい。
5. 案 B は 3D 最大だが、長さ・材質を隠すと現行操作と乖離し、移行リスクが高い。

案 A は C の「STAFF なし状態」そのものなので、実装は **まず A 相当のシェル → STAFF ワークスペースを載せる** 順が安全。

## 変更リスク（レイアウト共通）

1. `#panel` 固定幅前提の CSS が大量（`index.html` 内 style）。
2. 左バーは `main.js` が `document.createElement` している。HTML 化するとイベント二重登録に注意。
3. 見積 `#parts-table` / `#total` が DOM から消えると `calcAndRenderEstimate` が落ちる。
4. STAFF オーバーレイ HTML を消さずに移動しないと、ログインが死ぬ。
5. モバイルはどの案でも別途（viewport + ドロワー）。C でも初期はデスクトップ優先でよい。
