# V3 コマンドポップアップ仕様

作成日: 2026-10-15
ステータス: **設計のみ。** 初期実装は固定位置。ドラッグは将来。

---

## 1. 共通ルール

| 規則 | 内容 |
|------|------|
| 同時表示 | **1 つ**。新規オープン前に現在のポップアップを閉じる |
| 閉じるとき | 未確定の入力は捨てる。既存データは書き換えない |
| Esc | キャンセル（閉じる + 一時値破棄） |
| Enter | 確定。textarea・見積メモ等は例外（Ctrl+Enter またはボタン） |
| フォーカス | 開いたら先頭の入力へ。Tab で循環。最後から Shift+Tab でアイコンへ戻してもよい |
| 確定前 | プレビューのみ。`joints/beams` 等の永続配列を直接書き換えない |
| 対象変更 | 3D で別パーツを選んだら、ポップアップは「対象を更新して中身を読み直す」か「キャンセルして閉じる」。ツールごとに §3 |
| はみ出し | 画面内にクランプ |
| 3D | ポップアップ上のポインタは canvas に落とさない |

状態（実装時の案、未コード）:

```
window.__v3Cmd = {
  id: null,          // アイコン id
  modeSticky: false, // 追加モードなど、閉じてもモード維持
  target: null,      // 選択中パーツ
  draft: {},         // 未確定値
}
```

既存のモードフラグ（`isConnectModeOn`, `isLengthEditModeOn`, `isMoveModeOn`, `isBoardModeOn`）と二重管理しない。ポップアップ開閉はこれらを呼ぶラッパにする。

---

## 2. 確定 / キャンセル

**キャンセル（Esc、外側クリック※、別コマンドオープン時の前ポップアップ）**

- `draft` 破棄
- プレビュー消去 `hidePreview`
- 既存配列・保存ファイル・Firestore は触らない
- sticky モードは、仕様で「モードも OFF」と書いてあるもの以外は維持

※外側クリックで閉じるかはツールによる。追加モード中に 3D をクリックするのは「閉じる」ではなく「配置」なので、**3D クリックは外側とみなさない**。NORTH/WEST の別アイコンはみなす。

**確定（Enter / 確定ボタン）**

- 入力検証（空・非数は確定しない）
- 既存関数を 1 回呼ぶ（`apply-len-btn` 相当、材質適用、など）
- 成功後に `requestEstimateRender` は既存経路に任せる
- `saveHistory` は既存関数に任せる（ここで増やして 500ms 同期を刺激しない。同期は STAFF が collab 開始しているときだけ現行どおり）

---

## 3. ツール別：対象変更時

| ツール | 3D で別物を選んだとき |
|--------|------------------------|
| 追加 Beam/Pole/Joint | 選択は配置の一部。ポップアップの長さは維持 |
| 長さ変更 | 新しいコネクタを対象に `len-before` を読み直す。未確定ドラフトは捨てる |
| 材質 | 対象を更新。ドラフトの材質セレクトは維持してよい |
| 脚 | 対象 Joint を更新 |
| 削除 | 対象を更新。確定するまで消さない |
| 移動 | モード維持。ポップアップは説明のみなので中身更新不要 |
| 見積・寸法・ヘルプ | 選択変更で閉じない |
| STAFF ToDo 等 | 3D 選択と独立 |

---

## 4. キーボード

- ツールアイコンは `aria-pressed`（モード） / `aria-expanded`（ポップアップ）
- ポップアップは `role="dialog"` + `aria-labelledby`
- Esc はダイアログが先。モード OFF は 2 回目の Esc でもよい（追加モード）
- フォーカストラップはダイアログ内。閉じたら起動アイコンへ戻す

---

## 5. 既存 DOM との接続

推奨: **レガシーフォームを hidden で残し、ポップアップは見た目用**。確定時に

1. hidden の `#length-select` 等へ値を書く
2. 既存ボタン `#apply-len-btn` 等を `.click()`

または入力そのものをポップアップへ **move**（ID 維持）。move の方がイベントを張り直さなくてよい。

どちらでも ID リネームは禁止。

---

## 6. Undo との関係

- ポップアップを開いただけでは `saveHistory` しない
- 確定で既存ハンドラが history に載せる
- キャンセルは Undo スタックを汚さない
- 追加モードの 3D クリック配置は、現行どおりその関数が history を扱う（不揃いは既存課題。UI 層で無理に二重 save しない）

---

## 7. 見積更新

- 確定・3D 配置のあとは既存 `requestEstimateRender`
- ポップアップのドラフト変更では見積を動かさない（確定前破壊防止）
- NORTH 合計は `#total` のテキストを表示するだけ

---

## 8. 同期を誤って広げない

- ポップアップ開閉で `openStaffCollaboration` を呼ばない
- 自動レイアウト確定でも Firestore に書かない
- collab の `snapshotTimer` 500ms は STAFF が共同編集を開始したあと、現行コードが自ら回す。新 UI はそれを増やさない
